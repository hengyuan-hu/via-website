Abstract

Core Idea

  • Recast robot control as a visual tool-use task for agents, similar to general computer use.
  • Design a visual interface and a small set of versatile MCP tools for agents to see and command the robot.
  • Run off-the-shelf agents (Claude Code or Codex) to drive the interface and complete robot manipulation tasks, in simulation and on a real mobile manipulator.

Result Highlights

  • VIA solves diverse manipulation tasks zero-shot, reaching 100% with Codex Astra 6 and 85% with Claude Code Fable 5.
  • VIA drives a Stretch 4 mobile manipulator in the real world, succeeding in 24/25 episodes across five tasks that require both navigation and manipulation.
  • VIA scales with the underlying model, from 43% to 85% across the Claude Code tiers and from 38% to 100% across the Codex tiers, and it greatly outperforms a naive baseline that commands the robot without the interface.
  • VIA inherits strong reasoning, long-horizon planning, and closed-loop control capabilities from frontier agents for free.

Note

  • VIA is not Code-as-Policies (CaP). It involves no CaP-style code generation and provides no perception or skill primitives for the model to compose. In VIA, the agent is the policy, it closes the control loop itself rather than generating a program or invoking a learned policy to run the robot. VIA observes the UI through raw pixels (screenshots) and acts via low-level tools akin to mouse and keyboard operations in computer-use.
  • VIA opens up a new opportunity for leveraging state-of-the-art foundation models at scale in robotics, and demonstrates that with the right interface, robot control can become another economically valuable agentic task that benefits directly from modern models and agents.

VIA

Simulation Evaluation

We evaluate VIA on six tabletop manipulation tasks with a Franka Panda arm in robosuite, drawn from different benchmarks and together covering manipulation, physical reasoning, long-horizon planning, and precise execution.

Protocol

We use Claude Code (CC) and Codex as agents, each with three model tiers, to measure how VIA scales with the strength of the underlying model:

  • Claude Code with Sonnet 5 (medium), Opus 4.8 (large), and Fable 5 (extra large),
  • Codex with Terra 5.6 (medium), Sol 5.6 (large), and Astra 6 (extra large).

All agents run at xhigh reasoning effort. On top of a shared system prompt on how to use the interface, each task comes with a simple prompt that states only the task description and success condition. We evaluate every agent-model configuration over 10 seeds per task with varying initial object placements, and cap each episode at one hour of wall-clock time (two hours for Rainbow). Memory, internet search, and file access are disabled, so the agents can neither gain cross-episode experience nor read the simulator's source.

To isolate the benefit of VIA, we compare against a naive baseline that uses the same observations, agent, and controller but has no interface: it must issue commands to the controller for immediate execution, without probing and iterating in the virtual workspace. We also study a VIA-detailed variant whose task prompts add hand-written instructions with example lists of waypoints.

VIA solves diverse manipulation tasks zero-shot. Even the medium models reach around 40% success, and the high success rates on Turn on stove and Open drawer show that VIA handles articulated objects beyond simple pick-and-place. On Rainbow, the agents always plan carefully before moving any block, choosing the ordering, and even the direction of the arc, that needs the fewest moves. T-block remains challenging for all but Astra 6: every agent works out that the bottom block must be rotated by 45 degrees to increase the contact area, but most fail to place the green blocks within the roughly 8 mm tolerance of the task.

VIA scales with the capacity of the underlying model. Success improves from 43% to 85% across the Claude Code tiers and from 38% to a perfect 100% across the Codex tiers, with no fine-tuning: VIA benefits directly from the scale of the models it runs on.

VIA greatly outperforms the baseline. Without the interface, the same agents perform poorly in every configuration except Astra 6, where the interface still lifts the score from 93% to 100%. The strong baseline result of Astra 6 is consistent with recent demonstrations of zero-shot robot control with it; comparing across models quantifies this step change and shows how poorly prior frontier models do without VIA.

Default versus detailed prompts. VIA can also improve without any gradient-based training, for example by optimizing its prompts. As a case study, we manually write detailed instructions for five tasks explaining how we would complete them with the interface, including example lists of waypoints, and feed them to the large configurations (CC Opus 4.8 and Codex Sol 5.6) as additional prompts.

The instructions help modestly, improving the average success rate by 14% for CC Opus 4.8 and by 6% for Codex Sol 5.6. The remaining failures vary from task to task: T-block failures are primarily due to imprecise perception and execution, while Sol 5.6's drawer failures come from opening the wrong drawer, which the instructions do not specifically emphasize. Having the agents review their own failures and optimize their prompts may be a more promising direction than writing instructions by hand.

Real-World Evaluation

Instead of staying in the stationary tabletop domain, we run VIA on five real-world tasks with a Stretch 4 mobile manipulator that operates at room scale. The mobile robot allows a much wider range of initial conditions, as well as multi-step tasks in which the agent must remember objects that leave its view as the robot moves.

Unlike in simulation, where perfect depth yields dense, informative point clouds, the head-mounted lidar of Stretch 4 provides depth only for sparse points at room scale. VIA therefore uses purely 2D interface components on the real robot, rendering the target gripper on top of the head and wrist camera feeds, and lets the agent probe depth with hover. Depth in the wrist view comes from Fast-FoundationStereo on the wrist-mounted stereo camera. We evaluate VIA with Codex Astra 6 for five episodes per task.

VIA succeeds in 24 of 25 episodes, showing that it extends to real-world manipulation with commercial hardware; Towel and Wipe also extend the evaluation suite to deformable objects. The episodes exhibit several interesting behaviors:

  • Lamp: the task description mentions that the lamp is on a cabinet, and the agent searches for the lamp quickly once the cabinet appears in its view. In the one failure, the agent overextends the gripper and grabs the stem of the lamp instead of the chain, likely a perception problem since both are the same silver color.
  • Shelf: the head camera's limited field of view requires the agent to remember the locations of the lion and the drawer to move efficiently between them. VIA does this through the agent's built-in context management, without any additional engineering.
  • Towel: the agent folds the towel precisely so that the edges align well.
  • Wipe: the agent's view is blocked while wiping, so it moves the gripper away after a few wipes to check the cleanliness of the table. In one episode it drops the wipe and pushes it with a closed gripper after holding it fails to wipe cleanly.
  • Basket: the agent automatically retries within an episode when the lid slips out of the gripper during opening.
